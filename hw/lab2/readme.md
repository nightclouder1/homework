### Часть 2. Изучение таблицы МАС-адресов коммутатора
#### Шаг 1 Запишите МАС-адреса сетевых устройств.
```
PC1, PC2 > ipconfig /all.
```
MAC-адрес компьютера PC-1: 000C.CFD9.7333;
MAC-адрес компьютера PC-2: 0060.7032.3824
```
S1, S2 # show mac address-table
```
МАС-адрес коммутатора S1 Fast Ethernet 0/1: 0001.c9d7.1101;
МАС-адрес коммутатора S2 Fast Ethernet 0/1: 00e0.f9e3.1b01

#### Шаг 2 Просмотрите таблицу МАС-адресов коммутатора.
```
S2 # show mac address-table
```
```
          Mac Address Table
-------------------------------------------

Vlan    Mac Address       Type        Ports
----    -----------       --------    -----

   1    00e0.f9e3.1b01    DYNAMIC     Fa0/1
```
*Записаны ли в таблице МАС-адресов какие-либо МАС-адреса? Нет, имеется mac-адрес только самого коммутатора, так как коммуникация в сети не происходила.*
*Какие МАС-адреса записаны в таблице? С какими портами коммутатора они сопоставлены и каким устройствам принадлежат? Игнорируйте МАС-адреса, сопоставленные с центральным процессором. В таблице записан только один MAC-адрес самого устройва, который сопоставлен с 1 портом устройства.*

*Если вы не записали МАС-адреса сетевых устройств в шаге 1, как можно определить, каким устройствам принадлежат МАС-адреса, используя только выходные данные команды show mac address-table? Работает ли это решение в любой ситуации? Можно отправить эхо запрос на коммутатор, и посмотреть mac-адрес компьютера в ARP-таблице коммутатора.*

#### Шаг 3 Очистите таблицу МАС-адресов коммутатора S2 и снова отобразите таблицу МАС-адресов.
```
S2 # clear mac address-table dynamic
```
*Указаны ли в таблице МАС-адресов адреса для VLAN 1? Указаны ли другие МАС-адреса? Нет, не указаны, так как они не успели подгрузиться.*
*Через 10 секунд введите команду show mac address-table и нажмите клавишу ввода. Появились ли в таблице МАС-адресов новые адреса? Появился только mac-адрес самого коммутатора, новых адресов не появилось.*

#### Шаг 4 С компьютера PC-2 отправьте эхо-запросы устройствам в сети и просмотрите таблицу МАС-адресов коммутатора.
```
PC2 # arp -a
No ARP Entries Found
```
*Не считая адресов многоадресной и широковещательной рассылки, сколько пар IP- и МАС-адресов устройств было получено через протокол ARP? Никаких mac-адресов не нашло*
```
PC2 # ping 192.168.1.2
PC2 # ping 192.168.1.11
PC2 # ping 192.168.1.12

  Internet Address      Physical Address      Type
  192.168.1.1           000c.cfd9.7333        dynamic
  192.168.1.11          0001.420b.2360        dynamic
  192.168.1.12          00e0.f9bb.ebcb        dynamic
```
*От всех ли устройств получены ответы? Да, от всех, а так же эти устройства теперь отображаются в ARP таблице*
```
S2#show mac address-table 

          Mac Address Table
-------------------------------------------

Vlan    Mac Address       Type        Ports
----    -----------       --------    -----

   1    0001.420b.2360    DYNAMIC     Fa0/1
   1    000c.cfd9.7333    DYNAMIC     Fa0/1
   1    0060.7032.3824    DYNAMIC     Fa0/18
   1    00e0.f9e3.1b01    DYNAMIC     Fa0/1
```
*Добавил ли коммутатор в таблицу МАС-адресов дополнительные МАС-адреса? Если да, то какие адреса и устройства? Да, добавил: MAC-адресс PC1, MAC-адрес PC2, MAC-адрес S2, а также свой MAC-адрес.*

*В сетях Ethernet данные передаются на устройства по соответствующим МАС-адресам. Для этого коммутаторы и компьютеры динамически создают ARP-кэш и таблицы МАС-адресов. Если компьютеров в сети немного, эта процедура выглядит достаточно простой. Какие сложности могут возникнуть в крупных сетях? В крупных сетях таблица MAC-адрсов может переполниться. Гораздо тяжелей найти нужное устройство по MAC-адресу. Огромный ARP-кэш на шлюзах, который замедляет систему.*
